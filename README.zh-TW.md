# 泠靈小工具

**專為樂團譜務設計的模板化分譜管理系統。**

[English](README.md) | [繁體中文](README.zh-TW.md)

[首頁](https://suikann.github.io/ling-ling-suite/) | [隱私權政策](https://suikann.github.io/ling-ling-suite/privacy.html)

## 專案簡介

**泠靈小工具**是一套桌面應用程式，旨在解決樂團譜務人員在處理分譜檔案時的命名、分割與整理需求。提供視覺化的 PDF 分割與旋轉、模板化批次重新命名、以及專案化的檔案管理工作流。

## 核心功能

### 模板化重新命名
使用變數語法自訂檔名格式：
- **範例：**`{序號}-{曲名}-{樂器}.pdf` 產生 `01-貝多芬第五號交響曲-Flute.pdf`
- **群組覆寫：**每個群組可使用自訂格式，完全取代命名格式

### 視覺化 PDF 分割
以縮圖介面將合譜 PDF 拆分為各樂器的獨立分譜：
- 點擊頁面縮圖標記分割點
- 色彩分區顯示，搭配樂器名稱指派
- 右鍵或雙擊放大預覽

### PDF 旋轉
依區段設定不同旋轉角度：
- 標記旋轉段落邊界（類似分割點）
- 每個段落獨立選擇角度（0/90/180/270 度）
- 覆寫前自動備份，支援復原

### PDF 壓縮
把太大的掃描分譜壓到 20MB 以下（工具選單的「壓縮 PDF」，或以「壓縮資料夾」連同子資料夾一起壓）：
- 先試無損壓縮，不夠再依序降到 300、200 dpi；黑白（1-bit）影像不降
- 壓完檢查結構、影像與畫面，沒過就判為壓縮失敗，不交出壞檔
- 輸出前逐份比較：縮圖上點選位置，兩個放大鏡對照原檔與壓縮後的同一小塊；也能用電腦的 PDF 閱讀器開啟。每份選「留下壓縮後的」或「不要這份」，全部確認後才輸出
- 輸出到原資料夾旁的「<原資料夾名>（壓縮）」，檔名與子資料夾照舊；已經不到 20MB 的原樣複製，原檔不動

### 預設樂器表
內建常見樂團的樂器表：
- 管弦樂團、管樂團、弦樂團
- 國樂合奏、絲竹室內樂
- 每個群組擁有獨立的樂器表

### 專案管理
- 儲存/載入專案檔（`.llproj`），保留所有設定
- 最近開啟的專案快速存取
- 每群組可指定總譜檔案（序號為 00）
- 依群組建立分譜資料夾

### 復原/重做
- 支援重新命名、分割、旋轉操作的復原
- 重新命名支援重做（Ctrl+Z / Ctrl+Y）
- PDF 旋轉覆寫前自動備份

### 雙語支援
- 繁體中文與英文即時切換，無需重啟
- 模板變數名稱自動轉換（序號/Number、樂器/Instrument 等）

## 下載

前往 **[Releases](../../releases)** 頁面下載最新版本，免安裝：

- **Windows**：下載 `LingLingSuite-portable.zip`，解壓即可使用
- **Linux**：下載 `LingLingSuite-x86_64.AppImage`，加上執行權限（`chmod +x LingLingSuite-x86_64.AppImage`）即可執行；先看下方的「Linux 注意事項」

升級後請不要再用舊版開啟新版存過的專案檔：舊版看不懂新的欄位，存檔時會把它們丟掉。新版遇到更新版本存的專案檔時會唯讀開啟，不能存檔。

## Linux 注意事項

AppImage 只支援 x86_64、glibc 2.39 以上（Ubuntu 24.04 以後、Debian 13、Arch 系、近年的 Fedora）。

- **選單捷徑與更新**：用 [Gear Lever](https://github.com/mijorus/gearlever) 匯入 AppImage，它會建立選單捷徑，也能檢查新版。不用 Gear Lever 時自己寫一份 `~/.local/share/applications/lingling-suite.desktop`，`Exec=` 填 AppImage 的完整路徑；檔名與 `StartupWMClass` 都要是 `lingling-suite`，視窗管理器才對得起捷徑與視窗：
  ```ini
  [Desktop Entry]
  Type=Application
  Name=Ling Ling Suite
  Name[zh_TW]=泠靈小工具
  Exec=/home/你的帳號/Applications/LingLingSuite-x86_64.AppImage
  Categories=Office;
  StartupWMClass=lingling-suite
  ```
- **中文字型**：泠靈用系統的字型，沒有中文字型時中文會變成方框。請安裝中文字型，例如 `noto-fonts-cjk`（Arch 系）或 `fonts-noto-cjk`（Debian、Ubuntu）
- **記住登入**：登入狀態存在系統的 Secret Service。GNOME、KDE 通常已經有；Hyprland 這類自己組的環境要自行安裝並執行 Secret Service（例如 `gnome-keyring`）。沒有時照樣能登入，只是登入狀態旁會寫「這次登入不會被記住：這台電腦沒有安全儲存」，下次開泠靈要重新登入
- **沒有 FUSE 時**：AppImage 開不起來、錯誤訊息提到 FUSE 時，改用 `APPIMAGE_EXTRACT_AND_RUN=1 ./LingLingSuite-x86_64.AppImage` 執行；每次啟動會先解開到暫存資料夾，開得比較慢
- **退回 X11 時**：有 Wayland 時泠靈直接用 Wayland。在 X11 下（或設了 `QT_QPA_PLATFORM=xcb`）執行時，系統要有 Qt 的 xcb 外掛需要的 `libxcb-cursor`（Debian、Ubuntu 叫 `libxcb-cursor0`）等 xcb 函式庫，缺了會出現 `Could not load the Qt platform plugin "xcb"`
- **系統的檔案對話框**：要用桌面環境自己的開檔、存檔對話框，安裝 `xdg-desktop-portal-gtk`，並在啟動時設 `QT_QPA_PLATFORMTHEME=xdgdesktopportal`（例如 `.desktop` 寫成 `Exec=env QT_QPA_PLATFORMTHEME=xdgdesktopportal /完整路徑/LingLingSuite-x86_64.AppImage`）；沒設時用 Qt 內建的對話框

## 快速開始

1. 啟動 `LingLingSuite.exe`（Linux 執行 `LingLingSuite-x86_64.AppImage`）
2. 透過**匯入**選單加入 PDF 檔案或資料夾
3. **建立群組**，每個群組代表一首曲目，或其中一個樂章
4. 切到群組分頁，在左側的**編制表**設定該群組的聲部（手動輸入或載入預設樂器表）；拖動聲部時分譜跟著走，這場缺的分譜取消勾選「本專案有」；各聲部的人數（最少、最多或「以上」）與群組的時長也在這裡填
5. 在底部**設定命名格式**（如 `{序號}-{曲名}-{樂器}.pdf`）
6. 點擊**預覽並重新命名**執行

## 譜庫

群組可以連到譜庫（社團 Google 試算表加 Drive）裡的一首曲目、版本與樂章。連上後編制與時長以譜庫為準：

- 按專案的**儲存**時，這個群組改過的聲部、順序、人數、時長與聲部組同時寫進譜庫；沒按儲存就不寫。只寫改過的格子，譜庫裡同一格被別人改過時，會先列出這次的全部改動，衝突的標紅讓你逐項選要用哪一邊
- 連錯時按編制表上方連線旁的「改連…」連到別處（沒有單純取消連線）。原處有這個群組寫進去、之後沒人改過的編制時，會問要不要撤掉：選「撤掉」，下次儲存時刪掉它新增的聲部、人數改回原值；之後被別人改過的不動，表上寫出誰在何時改過
- 斷網或寫不進譜庫時，專案照樣存檔，沒寫進去的改動在編制表標「未同步」並寫出譜庫現在的值；下次存檔或開啟專案時自動重試
- 開啟專案時從譜庫讀回編制：別人改過的人數與時長直接套用；聲部清單變了時，編制表頂端出現提示並標出增刪與移動的聲部，選「套用譜庫的」（分譜依聲部名稱帶著走，對不到的移到未分組）或「用專案的（存檔時寫回）」（存檔時先確認再寫進譜庫）；還沒選之前分譜照專案的清單配對與命名
- 聲部組對照是全社團共用的：在譜庫視窗按工具列的「聲部組對照」，每個聲部組一欄，把樂器拖到別的欄、按儲存才寫進譜庫；上方可以切換國樂團、管弦樂團，搜尋樂器，每個樂器標出譜庫裡用到幾首
- 在連到譜庫的群組刪除聲部，等於從樂譜刪除；這場只是缺某份分譜時，請取消勾選「本專案有」。已經有 Drive 檔案的聲部不能從群組刪除，要到譜庫視窗處理
- 譜庫視窗的「編制與分譜」頁：每個聲部的狀態依有沒有登記 Drive 檔案寫成「有」或「缺」。右邊列出版本資料夾裡沒登記的檔，選一個檔、再選左邊的聲部或總譜，按「指定」，按「儲存」才寫進譜庫；改編制也是按「儲存」才寫。指定給已登記了檔的聲部時，原本那份會丟進 Drive 垃圾桶，30 天內可以從垃圾桶救回
- **存入譜庫**（「譜庫」選單）：把已重新命名、已連到譜庫的群組的總譜與分譜上傳到那個版本的 Drive 資料夾並登記到聲部，子資料夾跟本機的輸出位置相同，本機那份不動。預覽列出每份檔要新上傳、更新、搬移還是跳過；專案要先存檔才能存入。重新存入改過的檔時更新同一個 Drive 檔案，Drive 留著舊版本；中途斷網或取消時已完成的保留，再按一次就補齊
- 存入之後本機的檔又被改過時，群組面板以橘字標出、寫「本機較新，還沒存入譜庫」，關閉專案時提醒一次，不必連網。存入之後再復原重新命名時照常復原，但譜庫裡的那份維持原樣，改好之後請重新存入
- **清除本機檔案**（「譜庫」選單）：確認 Drive 上有內容相同（MD5 一致）的一份之後，永久刪掉本機的總譜與分譜，連同清空的資料夾（往上刪到輸出位置為止；家目錄與桌面、文件、下載等系統資料夾不刪），不進資源回收桶。預覽的群組總表列出每個群組可清除、跟譜庫不一樣、還沒存入、譜庫裡沒有的份數與可釋放多少，勾選要清的群組；斷網時不能清除，專案要先存檔。清除後群組裡這些檔標「只在譜庫」，不算找不到的檔案，重新命名與存入譜庫會跳過它們；把檔放回原位就恢復正常
- **從譜庫下載回來**：群組裡有「只在譜庫」的檔時，群組分頁（以及重新命名預覽的說明旁）出現「從譜庫下載回來」，把檔放回清除前的路徑與檔名，資料夾被刪了就重建；清除後又重新存入過的，下載的是最新的那份。原位置已經有別的檔時不覆蓋，列出來。每份先下載成暫存檔、核對 Drive 的 MD5 一致才放好，中斷或不一致時不留半份檔案；可以取消，再按一次就補齊
- **從譜庫下載到自選的資料夾**：譜庫視窗的版本頁按「下載…」，勾選幾份檔或「整個版本」（保留子資料夾），選好資料夾就在背景下載；Linux 上沒有 Drive 同步程式也能拿到舊譜列印。資料夾裡已有同名檔時，內容相同就略過，不同就加「 (1)」，絕不覆蓋；下載同樣核對 MD5
- **撤銷存入**：存錯版本或樂章時，在譜庫視窗的版本頁按「存入紀錄…」，選那次存入按「撤銷存入…」，勾要撤銷的群組。那次新上傳的檔丟進 Drive 垃圾桶（30 天內可救回）並移除登記，那次蓋掉的舊內容 Drive 還留著就還原；之後又重新存入或在 Drive 上改過的不動，列出原因。本機已清除的群組先下載回原位並核對，下載不回來的群組不撤銷。可以勾選一起撤掉這個群組在那次存入之前寫進那處、之後沒人改過的編制（新增的聲部刪掉、人數改回原值），預設不勾
- **升級後請不要再用舊版泠靈開譜庫**：舊版的分譜狀態選單會建出假聲部，刪除會讓列號位移，更新時也會用舊資料蓋掉前幾欄

### 試算表被寫壞時

寫錯列、誤刪工作表時，以 Google 試算表的版本記錄還原（泠靈與 API 都不能還原版本）：

1. 用譜庫帳號在瀏覽器開啟譜庫試算表
2. 選「檔案」→「版本記錄」→「查看版本記錄」
3. 在右側挑出事情發生之前的時間點，確認內容正確
4. 按「還原這個版本」

那個時間點之後所有人對這份試算表的修改都會一起倒退，還原前先跟其他譜務確認，還原後再把之後該留的改動補回去。

## 發譜

社團設定（譜庫試算表的「社團設定」工作表）啟用 HuaXia 時，底部出現**發譜…**，把群組的聲部、人數、分譜與總譜放上華夏國樂社的 HuaXia。要以幹部的 Discord 帳號登入；HuaXia 合併泠靈的發譜函式之前不能用，按下時會說明。

- 專案要先存檔、樂團類型要是國樂團；還沒重新命名、沒填最少人數的群組這次不發，預覽寫出原因
- 預覽分五步：曲目（挑 HuaXia 上現有的或新建）、聲部（對到 HuaXia 的哪個聲部，人數與聲部組不同時預設覆寫）、檔案（每份取代同聲部泠靈上次發的那份，別人放的不動；超過 20MB 的先壓縮）、公演（要掛的場次）、確認
- 按下「發譜」後在背景發，主視窗照常可以編輯；發出去的是按下那一刻的檔與編制，之後的改動要再發一次。狀態列有「停止發譜」，主視窗下方是逐行紀錄，完成時列出沒發成的群組與原因，按「重新發譜沒發成的群組」只重發它們
- 傳到一半斷線或停止時，團員看不到半套譜；再按一次發譜會從中斷處接著做，已傳的檔不重傳，新建的曲目不會重複建；中斷時留在 HuaXia 上、沒登記的檔，下次發同一首時先清掉
- 每次發譜都記在譜庫的「發譜紀錄」工作表；寫不進譜庫時不發譜
- **撤回**：連錯曲目時，在譜庫視窗按「發譜紀錄」選那次發譜、按「撤回…」，勾要撤回的群組。撤掉那次放上去的分譜與總譜，連同那次新建、還沒排人的聲部；被取代的舊檔不會回來，人數、聲部組與場次不改回。撤回前看得到逐聲部撤回後的樣子與會缺譜的聲部；那次新建的曲目會留下一首空曲目，由幹部在網頁刪除

## 已知限制

- **路徑比對不分大小寫**：所有平台都把只差大小寫的路徑當成同一個檔。Linux 上同一資料夾同時有 `Flute.pdf` 與 `flute.pdf` 時，泠靈會把兩者當成同一個檔；搬移前會確認目的地是不是另一個檔，擋下覆寫，檔案不會損壞。
- **檔名照 Windows 規則清理**：Linux 上也把 Windows 不允許的字元（`< > : " / \ | ? *`）換成底線，因為檔案會上傳到 Drive、給 Windows 使用者下載。
- **Google 登入的名額**：泠靈內附的 Google 用戶端是未經 Google 驗證的正式版，終身最多讓 100 個 Google 帳號登入，所有社團共用。每個社團只用譜庫帳號登入就只佔一個名額，請不要拿個人帳號試用。名額用完時，已登入過的帳號照常使用，新的帳號會無法登入，要等維護者換上新的用戶端、發新版後重新登入。

## 開發者指南

**環境需求：**
- Python 3.12+
- PySide6、PyPDF2、PyMuPDF、send2trash

**從原始碼執行：**
```bash
git clone https://github.com/Suikann/ling-ling-suite.git
cd ling-ling-suite
pip install -r requirements.txt
python src/main.py
```

**執行測試：**
```bash
pip install pytest pytest-cov
python -m pytest tests/ -v
```

**打包為可攜式 EXE：**
```bash
build.bat
```

### 在 Linux 上從原始碼執行

套件裝在 repo 根目錄的 `.venv`（Debian、Ubuntu 要先裝 `python3-venv`）：
```bash
git clone https://github.com/Suikann/ling-ling-suite.git
cd ling-ling-suite
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
./run.sh
```

`run.sh` 有 `.venv` 就用 `.venv/bin/python`，否則用 `python3`；缺套件時會列出缺哪些並停下。

**執行測試：**
```bash
.venv/bin/pip install pytest
.venv/bin/python -m pytest tests/ -v
```

**建置資料夾版：**
```bash
./build.sh
```

`build.sh` 選 Python 的方式與 `run.sh` 相同，會裝 PyInstaller、執行測試，再建出 `dist/LingLingSuite/`。

**建置 AppImage：**建好資料夾版後執行 `scripts/build_appimage.sh`，它下載固定版本的 appimagetool 與 runtime、核對檢查碼，產出 `dist/LingLingSuite-x86_64.AppImage` 與 `.zsync`。本機建出的 AppImage 的 glibc 下限是本機的版本，要發佈的一律由 CD 在 `ubuntu-24.04` 上建置。

打包參數只有 `LingLingSuite.spec` 一份，`build.bat`、`build.sh` 與 CD 都只跑它。

## CI/CD

- **CI：**每次 push/PR 自動執行測試（Python 3.12，Windows 與 Linux）
- **CD：**推送 `v*` 標籤時建出 Windows 的 `LingLingSuite-portable.zip` 與 Linux 的 `LingLingSuite-x86_64.AppImage`（附 `.zsync`），兩者都建好才放進同一個 GitHub 發行版；手動執行（workflow_dispatch）只上傳成工作產物，不建發行版
  - 發行版不要勾「預發行版」（Set as a pre-release）：AppImage 內嵌的更新資訊只認最新的正式發行版（`latest`），勾了之後 Gear Lever 檢查不到這一版
- **Pages：**`website/` 是首頁與隱私權政策（繁體中文在根層，英文在 `en/`），`develop` 上它有改動時由 `.github/workflows/pages.yml` 發布到 GitHub Pages，網址為 `https://suikann.github.io/ling-ling-suite/`。repo 的 Pages 來源要設成「GitHub Actions」
  - 改用子網域：在 repo 的 Settings > Pages > Custom domain 填入子網域，並在 DNS 加一筆指向 `suikann.github.io` 的 CNAME 記錄；repo 裡的檔案都不必改（以 GitHub Actions 發布時 Pages 不讀 CNAME 檔）。設好後 `suikann.github.io/ling-ling-suite` 的網址會自動轉到子網域，上方的連結照常可用；網域不續約時清掉 Custom domain 就回到原網址。兩種情況都要把 Google Console 的首頁與隱私權政策網址改成實際的網址
  - 改了隱私權政策的內容時，同時改中英兩版與兩頁的生效日期
