# 編制與時長的定本放在譜庫，專案存檔時寫回

專案（`.llproj`）定位為演出結束即可丟棄的物品，但編制（聲部、順序、人數）與時長是樂譜的事實，下一次演出同一份樂譜還要用。我們決定：群組連到譜庫的某個版本的整首或樂章時，編制與時長以譜庫為定本，`.llproj` 只存快照；使用者按下專案的存檔時，泠靈同時寫入 `.llproj` 與譜庫的 Google 試算表，在譜庫視窗則按編制表的儲存才寫入。原則是「沒按儲存，就不寫進譜庫」。沒連到譜庫的群組，以及沒用譜庫的使用者，編制只存在專案裡。

## Considered Options

- 定本放在 `.llproj` 的群組，譜庫當範本，由使用者明確執行「存回譜庫」（第一輪拷問 Q39）：專案一丟，沒存回的編制就跟著消失。關閉前提醒也擋不住，因為「沒存回」這個狀態存檔後仍在，每次關閉都會跳出，接手的人很快就會習慣性按掉；使用者在檔案總管直接刪檔時，泠靈也沒有時機提醒。
- 定本放在群組，每次存檔整份寫回譜庫：打開去年的專案、隨手存一下，就會把譜庫蓋回舊值，而且沒有任何提示。
- 編輯當下就寫入譜庫，跟專案存不存檔無關：等於把「沒存檔就表示不要這些改動」的慣例套用到專案以外，譜務會在沒打算保留的嘗試中改到譜庫。

## Consequences

- 存檔只送出這次改過的格子，不送整份快照；寫入前重讀譜庫，若別人改過同一格就逐項列出，由使用者決定是否覆寫。
- 寫不進譜庫（斷網、API 失敗）時專案照樣存檔，沒寫進去的改動標成「未同步」，下次存檔或開啟時重試；分割與重新命名不因譜庫連不上而停擺。
- 分譜依位置配對聲部，所以開啟專案時若譜庫的聲部清單或順序變了，必須先列出差異請使用者確認，不能默默套用；「這場缺某一份分譜」以專案層級的標記處理，不得以刪除聲部代替，因為在連到譜庫的群組刪除聲部就等於從樂譜刪除。
- 譜庫的結構只在既有工作表後面加欄、另開新工作表：程式依程式碼內的欄位常數讀寫，寫入只寫前 N 欄，舊版泠靈讀不到新欄也不會蓋掉。
- 聲部組不屬於個別樂譜，而是社團的歸類慣例，改由譜庫一張全社團共用的對照表記錄（樂團類型 × 聲部名稱）。
