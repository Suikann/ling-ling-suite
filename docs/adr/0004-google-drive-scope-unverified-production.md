# Google 權限範圍保留 `drive`，以未經驗證的正式版發布，內附用戶端給所有社團共用

譜庫建立在 Drive 上：曲目、版本的資料夾與分譜多半是譜務在 Drive 網頁上手動建立、上傳的，泠靈要能列出、改名、搬移與下載這些檔案。我們決定泠靈繼續要求受限範圍 `drive`（加上 `spreadsheets`），不送 Google 審查，把維護者 Cloud 專案的 OAuth 同意畫面從「測試中」切成「外部、正式版」，並在公開發行版內附這個專案的用戶端，所有社團共用，不提供「匯入自己的用戶端」。Google 一律登入社團的譜庫帳號，所以未經驗證正式版的 100 人終身上限，每個社團只佔一個名額。

## Considered Options

- 只要求 `drive.file`，經桌面 Picker 選譜庫根資料夾：非敏感範圍，免驗證、沒有人數上限，也沒有「Google 尚未驗證」的畫面。實測（2026-10-13）時，Picker 選資料夾只授權資料夾本身，選取前已在裡面的子資料夾列不出來；現有譜庫的版本資料夾全是手動上傳的 PDF，逐份挑選不可行。
- 送受限範圍審查：約 6 週、每年重審，可能要做 CASA 安全評估。Google 的最小範圍政策也可能以「只是上傳、下載特定檔案」為由駁回。每年都得有人接手送審，與「下一任只要會用」的傳承標準衝突。
- 學校 Google Workspace 的「內部」應用程式：只有該校帳號能授權，與「泠靈是公開的通用工具」衝突，學校管理員也可能擋下第三方 app。
- 停在「測試中」：授權自同意起 7 天失效，每週都要重新登入，安全儲存裡的續期權杖撐不過一週。
- 社團匯入自己的用戶端：每個社團要自建 Cloud 專案、當場下載只給一次的用戶端密鑰，可能還要處理帳單，超出「下一任只要會用」。上限以 Google 帳號計，各社團只以譜庫帳號佔一個名額，匯入解決的問題並不存在。

## Consequences

- 每個帳號第一次授權時，會先看到「Google hasn't verified this app」，要按 Advanced 才能繼續；同意畫面讓使用者逐項勾選範圍，泠靈登入時要檢查實際拿到的範圍，缺一個就不保存權杖。
- 100 人上限以 Cloud 專案為單位、終身累計、不能重置。會佔名額的只有維護者的測試帳號、各社團的譜庫帳號與用其他帳號試用的人。用完時已授權的社團照常使用，只有新帳號被擋；補救是維護者另建 Cloud 專案、換上新用戶端發新版，各社團重新登入一次。
- 換了用戶端，安全儲存裡的舊續期權杖就換不到新權杖，泠靈照「Google 不認這個權杖」處理，發行說明寫一句。
- 正式版的發布要求首頁與隱私權政策網址：兩頁放本 repo 的 GitHub Pages、綁維護者網域下的子網域。名稱與圖示要通過品牌驗證才會顯示在同意畫面上，未驗證時只顯示網域。
- Cloud 專案歸維護者的個人帳號，不設第二擁有者：唯一擁有者刪除帳號時專案跟著被刪；用戶端連續 6 個月沒有權杖請求也會被自動刪除。這兩項是接受的風險。
- 維護者打算停止維護泠靈，或 Google 停用、限制這個未經驗證的 app 時，要重新考慮「匯入自己的用戶端」或換掉 Drive，兩者都是另一件工作。
