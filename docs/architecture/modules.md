# Modules

各檔的用途寫在檔首的模組 docstring，分層見 [CODING_STANDARDS.md](../../CODING_STANDARDS.md)。本檔只記 docstring 與檔名看不出的事：哪些職責全程式只有一個入口、測試怎麼寫。

## 唯一入口

下列職責全程式只在一處實作，新程式碼經過它：

| 職責 | 入口 |
|------|------|
| 判斷兩條路徑是否同一個檔（絕對路徑、不分大小寫） | `core/paths.py` 的 `path_key`、`same_path`、`is_inside`；沒有本機路徑的名稱（Drive 檔名）用同一規則的 `name_key` |
| 判斷兩個聲部名稱是否同一聲部（結尾編號互通）或同一樂器（去掉結尾編號） | `core/voice_names.py` 的 `same_voice`、`voice_key`、`same_instrument`、`instrument_key`；規則寫死在模組 docstring。依名稱配對分譜、同一份樂器表不重名（`duplicate_rows` 列出重名的列，`voice_index` 找同一聲部的第一列）、發譜對到 HuaXia 聲部、依聲部配值（`match_by_voice`：舊專案人數展開、換樂器表時沿用人數、複製編制）、自動完成的同名標記都經它，同一樂器只用在聲部組對照的鍵。只用於比對，各處保留自己的寫法；檔名與路徑用上一列的 `name_key`、`path_key` |
| 聲部名稱的自動完成（候選來源、排序與「同一聲部」標記） | 候選在 `core/voice_suggestions.py`：`VoiceCandidates` 全程式一份，由 `MainWindow` 建立後交給編制表、分割視窗與譜庫視窗；譜庫視窗讀到總覽時記下譜庫用過的聲部名稱（`CatalogOverview.voice_names`，依使用次數排序，與總覽同一次試算表讀取），還沒讀過譜庫時候選是專案其他群組的名稱加上預設樂器表；`suggest` 列出包含輸入文字或同一聲部的候選。欄位掛上自動完成經 `ui/voice_completer.py` 的 `attach_voice_completer`（表格的編輯欄用 `VoiceNameDelegate`）。只提示、不改寫輸入，也不參與比對 |
| 聲部清單換成譜庫的時，分譜依聲部名稱帶著走（依名稱配對）與套用前的預覽 | `Project.apply_catalog_voices`；預覽每個聲部配到的分譜是 `Project.merge_rows`，兩者同一套規則（見 [project.md](project.md) 的連到譜庫）。連線選用譜庫的經它，開啟專案時套用譜庫的新清單也沿用，不另寫一份配對 |
| 聲部的聲部組（以樂器為鍵的對照，沒存的依樂團類型偵測） | `core/sections.py` 的 `section_for`（專案裡經 `Project.section_of`）；寫入經 `Project.set_section`、`update_sections`（見 [project.md](project.md)） |
| 編輯一個群組的編制（聲部、本專案有、人數、聲部組、時長；拖動時分譜跟著走） | `ui/instrumentation_table.py` 的 `InstrumentationTable`：主視窗左欄用它，其他視窗要顯示編制（例如譜庫視窗的版本頁）時沿用、不另做一份；帶入專案後以 `show_group` 顯示群組，修改經 `Project` 的編輯操作（見 [project.md](project.md) 的編制表） |
| 人數範圍的整理與 HuaXia 記法（`6`、`6-8`、`2↑`） | `core/models.py` 的 `Headcount`（`normalized`、`text`、`filled`）；合計用 `sum_headcounts`，時長的「分:秒」用 `format_duration` |
| 依介面語言挑選中英文版本 | `core/locale.py` 的 `is_english`、`localized` |
| 可選的介面語言與它們的名稱 | `core/locale.py` 的 `language_names`：檢視選單的語言與譜庫設定的欄位語言選單共用 |
| 檔名清理（非法字元換底線、空名回退）與同名後綴（「 (1)」） | `core/filename.py`：清理由重新命名與分割共用，同名後綴 `numbered` 由重新命名的重複目標與從譜庫下載的同名檔共用 |
| 一格（總譜或第 N 份分譜）的檔名與資料夾；群組是否已重新命名（檔都在命名結果的位置，存入譜庫與發譜共用） | `core/naming.py`（見 [naming.md](naming.md)）；已重新命名是 `is_renamed`，單一份檔是 `is_named_at` |
| 走訪專案引用的檔案（總譜＋分譜＋未分組）；依路徑取代、移除引用 | `Project.file_refs()`、`Project.replace_paths`、`Project.remove_paths` |
| 群組欄位的編輯規則 | `Group.update`；不屬於專案的 Drive 群組也用它 |
| 畫面上代表群組的文字（群組名稱，空白時用群組 ID 前 8 碼） | `Group.display_name`：群組分頁的標籤、主視窗勾選群組的清單、群組面板的移動選單、連結樂章與旋轉、分割的群組篩選都用它 |
| 讀寫譜庫（Google 試算表與 Drive） | `services/catalog_service.py` 的 `CatalogService`：UI 與其他服務只呼叫它，失敗時丟出帶錯誤類別的 `CatalogError`（`core/catalog_errors.py`），不以空值或空清單代表失敗。它對下只經過試算表與 Drive 兩個關口（`services/catalog_ports.py` 的 `SheetsPort`、`DrivePort`，一次呼叫一次請求）；接 Google 的通事是 `services/google_catalog.py`，全程式只有它匯入 `googleapiclient`、把 Google 的例外轉成錯誤類別。寫入的共用規則（值以 RAW 寫入、Drive 名稱搜尋的跳脫、429 退避重試、ID 撞號重抽、新增列重送不重複、建譜庫總表重送不建第二份）都在服務與通事裡。譜庫視窗、Drive 重新命名、譜庫設定與群組連到譜庫（`read_place`、`create_place`，見 [project.md](project.md) 的連到譜庫）、開啟專案時更新快照（`read_places`，一處已不在譜庫時只有那一處是 None，見 [project.md](project.md) 的開啟時更新快照）、存檔時寫回編制（`sync_instrumentation`，格子的拆分與比對在 `core/catalog_sync.py`，見 [project.md](project.md) 的寫回譜庫）、改連時撤得掉的原處編制（`revert_rows`，判斷在 `core/catalog_revert.py`，撤銷存入共用；見 [project.md](project.md) 的改連）、譜庫視窗編輯全社團的聲部組對照（`section_map`、`sync_section_map`，與寫回同一套比對）、版本頁（`edition_page` 讀編制、登記的檔與版本資料夾裡全部、沒登記的檔，`register_files` 登記檔並把換掉的舊檔丟進 Drive 垃圾桶，見 [project.md](project.md) 的版本頁）、存入譜庫（`place_files`：各處的登記與版本資料夾的檔，清除本機檔案與下載回原位共用，已不在譜庫的那處不在結果裡；`drive_ids`、`begin_deposit`、`upload_file`、`update_file`、`place_file`、`record_deposits`、`deposit_log`）、從譜庫下載（`download_file`）、撤銷存入（`deposit_log`、`revert_reading`、`drive_file`、`trash_file`、`restore_revision`、`record_revert`）、發譜紀錄（`begin_publish` 在發譜動 HuaXia 之前寫「開始發譜」並抽發譜編號，`record_publish` 結束後補「發譜結果」，`publish_log` 讀回；一列的內容在 `core/publish_log.py` 的 `PublishRecord`）的讀寫都經它；要刪改試算表的列時，寫入前一刻才讀列號（`update_record`、`delete_*`） |
| 譜庫總表標題列的語言（各工作表的中英文欄名、從標題列認出語言） | `core/catalog_headers.py` 的 `header_row`、`header_locale`、`catalog_header_locale`；中文欄名是 `core/catalog_constants.py` 的 `SHEET_HEADER_NAMES_ZH`，英文欄名就是 `SHEET_HEADERS` 的欄位鍵，社團設定兩種語言相同。建立譜庫總表、寫入時補標題與新建工作表、譜庫設定的欄位語言選單（`CatalogService.header_locale`、`set_header_locale`）都經它；讀寫照欄位位置，不看標題文字 |
| 存入譜庫：哪些群組能存入、每份檔放在版本資料夾的哪裡與要做的事（新上傳、更新、搬移、登記、跳過），以及照計畫上傳與登記 | 規則在 `core/deposit.py`（`deposit_sources`、`plan_group`）；讀本機檔案的 MD5 與照計畫執行在 `services/deposit_service.py` 的 `DepositService`（`preview`、`deposit`），碰譜庫經譜庫服務；存入指紋交回專案經 `Project.record_deposit`（見 [project.md](project.md) 的存入譜庫） |
| 清除本機檔案：每份檔的歸類（可清除、跟譜庫不一樣、還沒存入、譜庫裡沒有、只在譜庫）、要刪的空資料夾，以及照計畫永久刪除 | 規則在 `core/clear_local.py`（`clear_sources`、`classify`、`emptied_folders`）；讀本機 MD5、讀譜庫與刪檔在 `services/clear_local_service.py` 的 `ClearLocalService`（`preview`、`clear`），碰譜庫經譜庫服務的 `place_files`。永久刪除（`FileService.delete_permanently`）只有它使用，其他刪除使用者檔案的操作一律走資源回收桶（`FileService.delete_file`）（見 [project.md](project.md) 的清除本機檔案） |
| 從譜庫下載：下載回原位（只在譜庫的檔放回清除前的路徑）與一般下載（版本資料夾的檔下載到自選的資料夾），先存成暫存檔、核對 Drive 的 MD5 才放到正式位置，絕不覆蓋 | 要下載哪些檔、放哪裡在 `core/catalog_download.py`（`restore_items`、`folder_items`）；下載與核對在 `services/download_service.py` 的 `DownloadService`（`restore_sources`、`restore`、`download`；撤銷存入先放回本機已清除的檔用 `put_back`），各入口共用，碰譜庫經譜庫服務的 `place_files`、`download_file`（見 [project.md](project.md) 的從譜庫下載） |
| 撤銷存入：存入紀錄分成一次一次的存入、每份檔撤銷後的下場（丟進垃圾桶、還原舊版本、只移除登記、無法還原、不動）、會毀掉唯一一份而不撤銷的群組、本機已清除的先下載回原位，以及一起撤掉的編制 | 規則在 `core/deposit_revert.py`（`deposits`、`revert_preview`，開著的專案是 `LocalProject`）；查本機有哪些檔與照決定去做在 `services/deposit_revert_service.py` 的 `DepositRevertService`（`preview`、`revert`；譜庫視窗經主視窗的 `revert_reader` 讀預覽），下載回原位經 `DownloadService.put_back`，編制的撤掉經 `sync_instrumentation`（`core/catalog_sync.py` 的 `revert_write`，與改連共用）；指紋交回專案經 `Project.record_fingerprints`、`Project.forget_deposits`（見 [project.md](project.md) 的撤銷存入） |
| 一份檔是不是只在譜庫（本機沒有、譜庫裡有一份） | `Group.has_catalog_copy`（群組記著譜庫裡有一份）加上本機找不到，不另外存；有一串找不到的路徑時以 `Project.catalog_only_paths(missing)` 挑出；從一串路徑查本機在不在、再挑出只在譜庫的經 `DepositService.catalog_only`（群組面板、撤銷存入前）。開啟專案、群組面板、重新命名預檢（`RenamePlan.catalog_copies`）、存入譜庫（`DepositSource.catalog_copy`）與清除本機檔案（`ClearSource.catalog_copy`）都以它判定（見 [project.md](project.md) 的只在譜庫） |

| 社團設定的發譜平台（發譜功能顯示與否） | `services/club_settings_service.py` 的 `ClubSettingsService`：`read` 經 `CatalogService.publishing_platform` 讀譜庫的社團設定工作表並記在偏好設定，讀不到時丟出 `CatalogError`、記住的不變；連上譜庫時改用 `refresh`，讀不到時記住的不變、失敗寫進紀錄檔，不顯示提示列；`remembered` 只看偏好設定，啟動時用它決定顯示與否，譜庫設定也以它寫出記住的發譜平台（照社團設定裡的寫法，沒有時寫未設定）與到社團設定工作表設定；譜庫設定按「儲存設定」一律在背景以 `refresh` 重讀，存了另一份譜庫總表時先以 `forget` 清掉。服務全程式一份，由 `MainWindow` 建立後傳給譜庫視窗與譜庫設定；記住的結果寫入後（讀到了、`forget`）通知 `subscribe` 的訂閱者（在寫入的執行緒呼叫），主視窗經 Qt 訊號轉回主執行緒更新「發譜」，開著的譜庫設定同樣改寫記住的發譜平台那一行、顯示或藏起 HuaXia 登入區，關閉或刪掉時 `unsubscribe`；訂閱者丟出例外時寫進紀錄檔，其餘的照常通知 |

| 發譜前的檢查（spec #82）：擋下整個發譜的（未存檔、不是國樂團）、擋下個別群組的（還沒重新命名、沒填最少人數、樂器表重名）與只標出的未同步值；按下發譜時 HuaXia 那一側的重查幹部身分、發譜函式的介面版本與可以挑的曲目（連同它們已有的聲部，`HuaXiaClient.piece_parts`；資料表經 `HuaXiaClient.select_all` 只讀這幾首曲目的、分頁讀完） 聲部之間配，分部依所屬聲部列出、名稱對到分部的列標出；要新建的聲部可以把勾選的 HuaXia 聲部收成分部，`PublishPreview.set_absorb`；這次要發的聲部先配，本專案沒有、也不在 HuaXia 建的只在剩下的裡配，不占要發的聲部可以挑的；算出新建與覆寫，沒有刪除），手動挑的配對經 `Project.choose_huaxia_part` 記住。「檔案」步每份檔要取代的與別人放的是同一檔的 `plan_files`（同一個聲部底下、泠靈發的那份，總譜是聲部空白的；以泠靈的 Storage 路徑格式辨認，格式在 `services/huaxia_client.py` 的 `lingling_storage_path`、`is_lingling_path`，照 HuaXia ## 測試

- 一律以 pytest 執行：`tests/conftest.py` 在任何測試模組匯入前把使用者資料目錄（`APPDATA_DIR`）導到臨時目錄，只有 pytest 會載入它（直接執行測試檔時不會，測試可能寫進真實的使用者資料目錄）。它也關掉自動垃圾回收，改在每個測試收尾後於主執行緒回收：測試留下的 Qt 物件不會在背景執行緒（例如壓縮）被解構而 segfault（`tests/test_garbage_collection.py` 釘住）
- UI 接線測試在匯入 PySide6 之前設定 `os.environ.setdefault("QT_QPA_PLATFORM", "offscreen")`，只測與服務層的接線、不測畫面，不需要顯示器
- 共用 fixture：
  - `tests/path_spellings.py`：同一路徑的不同寫法（大小寫、相對路徑、多餘分隔符），測路徑比對
  - `tests/failing_writes.py`：寫到（原子寫入或附加）指定檔案就失敗的 `FileService`，注入給要測寫入失敗的服務
  - `tests/other_instance.py`：以子行程扮演另一個持有單一實例鎖的程式
  - `tests/memory_keyring.py`：記憶體裡的 keyring backend，注入給 `SecureStorage`；可設成沒有安全儲存、被鎖住、寫入或刪除失敗。測試一律注入它，不碰系統的安全儲存
  - `tests/fake_google.py`：Google 權杖端點的替身（兌換授權碼時回傳指定的續期權杖、範圍與帳號 email；續期時回傳指定權杖、拒絕續期、連不上），以及寫出測試用用戶端檔的 `write_client_secrets`
  - `tests/fake_google_catalog.py`：假 Google，記憶體裡的譜庫總表加 Drive，實作兩個關口，注入給 `CatalogService`；每次呼叫計為一次請求（試算表與 Drive 另外分開計數），可以設定第 N 次請求（或第 N 次上傳）丟出某類錯誤（可選擇請求生效之後才丟，扮演回應沒收到），或在第 N 次請求之前讓另一台電腦改動譜庫。Drive 的檔有各次內容的版本，以預先要到的 ID 建檔重送時回已經存在（409），可以讓某個檔下載時內容壞掉（`corrupt_downloads`），舊版本可以設成永久保留，也可以扮演 Drive 清掉了某個舊版本（`purge_revision`）；根資料夾照 Drive 有別名 `root`，回應的 `parents` 是它真正的 ID（`ROOT`）。譜庫讀寫的測試一律用它，不接真的 Google
  - `tests/fake_browser.py`：開瀏覽器的替身，注入給本機回呼與登入服務；拿到授權網址後在背景真的對其中的 `127.0.0.1` 回呼（`redirect_uri`，沒有時 `redirect_to`）送 HTTP 請求，帶 `code` 或 `error`，或設成永遠不送；建立時傳入提供者（例如假 HuaXia 的 `authorize`）時，授權碼由它依授權網址發給
  - `tests/fake_huaxia.py`：假 HuaXia，記憶體裡的 Supabase，當作 HTTP session 注入 `HuaXiaClient`：Auth（PKCE 兌換、續期與輪替，重用用過的續期權杖會撤銷 session、`scope=local` 與 global 登出）、PostgREST 的讀取（照 HuaXia 的 RLS，一次最多回傳 `max_rows` 列、多的要分頁，含曲目 `add_piece` 與聲部 `add_part`；聲部組沒給時照觸發器以 `guess_section` 補上，`remove_part`、`rename_part` 扮演幹部在網頁上刪改聲部；`add_part` 給 `parent_id` 是分部，`set_parent` 扮演幹部在網頁上設定所屬聲部，分部的規則照觸發器擋下、回 `23514`）、`rpc/is_officer` 與發譜函式和它的版本查詢（預設沒有，`install_publish_function` 裝上指定版本；發譜函式照 [docs/huaxia/LINGLING.md](../huaxia/LINGLING.md) 實作：全成或全不成、RLS、文件裡的錯誤代碼、介面版本 2 的收分部 `absorb`）、樂譜（`add_score`，`rename_score` 扮演幹部在網頁上改名）、學期、場次與曲目掛上場次（`add_semester`、`add_event`、`attach_piece`）、Storage 的列出、上傳（不覆寫）與刪除（`put_object` 放檔）、撤回與收回經 REST 的刪除（只有幹部刪得到樂譜與聲部，刪聲部連帶刪掉分部、排人與樂譜）與排人（`assign`）；可以讓某幾個請求斷線（`drop_requests`）或某首曲目的切換失敗（`fail_switch`）；新的 Discord 帳號第一次登入時建立待核准的帳號。可設成連不上，或讓續期卡住直到放行。HuaXia 的測試一律用它，不接真的 HuaXia
  - `tests/synthetic_pdfs.py`：以 PyMuPDF 產生的合成掃描分譜（8-bit 灰階、JPEG、1-bit、未壓縮的串流、加密、宣告錯誤的 JPEG），測壓縮服務與壓縮檢查；壓縮服務的測試不接替身，以注入的大小上限代替 20MB
