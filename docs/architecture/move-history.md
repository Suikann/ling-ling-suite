# Move History

搬移歷程（`services/move_history.py` 的 `MoveHistory`）是重新命名、復原、重做與中斷還原的唯一入口；它也擁有重新命名預檢、復原／重做堆疊、進行中紀錄與工作區 meta 快照，並組裝分割與旋轉的復原紀錄。檔案實際的搬動交給內部的兩階段引擎（`services/move_service.py` 的 `MoveService`）。主視窗只詢問與顯示。

## 重新命名預檢

- 檢查只做一次：`MoveHistory.check_rename(project, group_ids)` 以 `rename_service.generate_rename_plan` 產生計畫（`RenamePlan`），交給 `check_plan` 回傳判定 `RenameVerdict`：實際會執行的計畫（`plan`），加上以來源為鍵、分類好的問題（`problems`：來源 → `RenameProblem`）。給定的計畫也能直接以 `check_plan` 判定
- 預覽只顯示這份判定；按下執行時 `MoveHistory.rename(verdict)` 執行的就是它的計畫，判定有阻擋時不搬動任何檔案
- 預檢與執行前驗證共用引擎的同一套規則（`MoveService.find_problems`），預覽與執行不可能判得不一樣

### 問題的種類

`RenameProblem` 每種問題是否阻擋、預覽的訊息、執行前驗證拒絕時的訊息與檢查順序都只記在 `core/constants.py` 的 `RENAME_PROBLEM_RULES`，預檢、預覽與搬移引擎都查它。

不阻擋的只有三種，預覽列出、照常執行：

- 來源已不在（`MISSING_SOURCE`）：從計畫丟掉
- 目標重複（`SUFFIXED`）：自動加後綴（只加一次），預覽警告並把執行鈕改為「繼續（自動加後綴）」；加後綴後的計畫再檢查一次，仍重複（例如兩個檔要改成 Same.pdf、第三個要改成 Same (1).pdf）就以 `DUPLICATE_TARGET` 阻擋並列出撞名的檔
- 多於聲部數的分譜（`EXTRA_FILE`）：不改名

其餘種類一律阻擋、停用執行，預覽顯示原因：

- 目標路徑邊界（`OUTSIDE_OUTPUT`）：每個目標都必須在該項的輸出位置之內（`RenameEntry.output_location()`，沒指定輸出位置時為來源檔所在的資料夾；以 `core.paths.is_inside` 判定），只要有一個不在就整批阻擋。這是命名模組擋 `.`、`..` 之外的第二道防線
- 同一來源檔案被多個群組引用（`DUPLICATE_SOURCE`，無法自動修正，需使用者調整群組）、產生的檔名去掉副檔名後為空（`EMPTY_NAME`）、目標位置已有不屬於本次計畫的檔案（`TARGET_OCCUPIED`）、讓位用暫名已被佔用（`STAGING_TAKEN`）；「佔用」的定義見下方[對調、連鎖與暫名](#對調連鎖與暫名)

判定另有三個欄位不在 `RENAME_PROBLEM_RULES` 裡：是否阻擋寫在 `RenameVerdict.blocked`，預覽訊息寫在 `ui/preview_dialog.py`。

- `unsafe_folder`（阻擋）：資料夾名稱清理後是 `.` 或 `..`（見 [naming.md](naming.md)）
- `folder_variables`（阻擋）：子資料夾模板用了逐檔變數（見 [naming.md](naming.md) 的子資料夾輸出）
- `unknown_variables`（不阻擋）：命名格式與子資料夾模板裡的未知變數，已從名稱拿掉

## 動作與結果

- 重新命名 `rename`、復原 `undo`、重做 `redo`、中斷還原（「還原」`recover`、「保留結果」`keep_result`）四個動作都回傳 `MoveResult`；沒有可復原或可重做的紀錄時，`undo`、`redo` 回傳 `None`
- `MoveResult`：`changes`（照計畫搬好的檔，動作前位置 → 目前位置）、`skipped`（已不在預期位置而略過的檔）、`residual`（搬不回原位的檔）、`operation`（操作種類，`core/constants.py` 的 `OperationKind`）、`error`（失敗原因）、`record_error`（檔案已搬好但紀錄寫不進去的原因）；復原分割時另有 `split`（該次分割的 `SplitRecord`）
- 主視窗把 `changes + residual` 交給 `Project.replace_paths`、`split` 交給 `Project.revert_split` 套用

## 兩階段搬移引擎

### 執行前驗證

`MoveService` 搬動前先以 `find_problems` 驗證：目標在輸出位置邊界內（只有重新命名有邊界，復原、重做沒有）、新檔名不為空、來源存在、來源未重複、目標未重複、目標未被計畫外的檔案佔用、讓位用的暫名未被佔用。任一不符即整批取消：結果帶 `error`、沒有路徑變動。

### 對調、連鎖與暫名

「佔用」指磁碟上存在、且不是本次計畫任何一筆的來源，所以對調（A→B、B→A）與連鎖（A→B、B→C）可以執行：來源同時是其他項目目標的檔案，第一階段先改成同資料夾的 `<原檔名>.moving` 暫名（`RENAME_STAGING_SUFFIX`）讓出位置，第二階段全部就位。復原紀錄只記原始位置到最終位置，暫名不出現。

跨磁碟的一步由 `FileService.rename_file` 先複製到 `<目標>.part` 再就位，失敗不在目標留下半成品。

### 回滾與殘留紀錄

- 執行中途失敗則依搬移的反序回滾至原位；回滾也失敗的檔案（含停在暫名者）列在 `residual`
- 搬移歷程替它們寫一筆殘留紀錄（`residual` 為真，`operation_type` 為留下它的操作：重新命名、復原或重做，描述如「復原失敗後留下的 N 個檔案」），放上復原堆疊、不清空重做堆疊，UI 套用其路徑，不留下無紀錄的半完成狀態
- 殘留紀錄與（復原時的）工作區 meta 寫回都經引擎的 `on_rollback`，在刪除進行中紀錄之前完成
- 已知缺口：殘留紀錄寫不進去時只放進 `record_error`，引擎照樣刪除進行中紀錄（`MoveHistory` 內的 `rolled_back`），這些檔就沒有任何紀錄

## 進行中紀錄與中斷還原

程式被中途關掉（當機、斷電、強制結束）也不留下無紀錄的狀態，靠的是進行中紀錄（`MOVE_JOURNAL_FILE`）：它是這批搬移的 write-ahead log，每一步先記再搬，正式紀錄寫完才刪除。

### 進行中紀錄的內容與寫入時機

- 引擎在搬第一個檔案前就把進行中紀錄原子寫入，內容是目前仍生效的步驟清單、即將執行的下一步（`pending`），以及這批搬移的來歷（`BatchContext`）：操作種類（`operation`：重新命名、復原或重做）、所屬復原紀錄的 id（`record_id`）、該紀錄在搬移開始時的內容（`record`，含工作區 meta 快照）與所屬的專案檔（`project_path`：`rename`、`undo`、`redo` 由主視窗傳入，專案尚未存檔為空字串）
- 每完成一步就把該步加進清單、下一步記為 `pending` 重寫；回滾與還原每逆轉一步就從清單移除並存檔，開始逆轉時也取消 `complete`。紀錄隨時反映每個檔案的實際位置
- 整批搬完先標記 `complete`，由搬移歷程寫正式紀錄（重新命名寫復原紀錄並清空重做堆疊；復原寫回工作區 meta、轉入重做堆疊；重做轉回復原堆疊），寫完才刪除進行中紀錄，兩者之間沒有空窗
- 正式紀錄寫不進去（例如磁碟已滿）時，結果仍帶 `changes`，專案路徑照樣更新到檔案的實際位置，`record_error` 只提示；進行中紀錄保留，下次依操作種類提示「上次…已完成」，可選保留結果或還原
- 還原與保留結果也照這個順序：紀錄寫不進去就保留進行中紀錄，下次再處理。工作區 meta 寫回失敗不在此列，只略過（見[工作區 meta 快照](#工作區-meta-快照)）
- 紀錄仍在時，引擎以 `PendingMoveError` 拒絕執行新批次（否則會蓋掉唯一的紀錄），訊息請使用者先處理中斷提示
- `load_pending` 對照磁碟判定 `pending` 那一步（來源已不在、目標已出現＝已完成），補上「搬完、來不及記就當機」的那一步；比對用 `file_exists_exact`（目錄列表的實際名稱），只改大小寫的那一步在不分大小寫的檔案系統上才判得出

### 中斷提示：還原、保留結果、稍後

- 啟動時 `MainWindow.prompt_pending_recovery` 以 `MoveHistory.pending()` 查看進行中紀錄是否仍在，提示依被中斷的操作種類說明（「上次重新命名／復原／重做未完成」）；重新命名、復原、重做前也會再問一次
- 未搬完時提示「上次…未完成（已搬移 N 個檔案）」：「還原」由 `MoveHistory.recover()` 依生效清單反序搬回（與回滾共用 `_reverse_all`，對調、連鎖、停在暫名者都能還原，還原途中再被中斷也能接續）；「稍後」保留紀錄，下次再問
- 已搬完（`complete`）但正式紀錄未確認寫入的，多一個「保留結果」（`MoveHistory.keep_result()`）
- 兩個選擇都讓堆疊與檔案位置一致，已寫過的紀錄不重寫：
  - 「還原」讓堆疊回到這批搬移開始前：被中斷的復原，其紀錄留在（或放回）復原堆疊、不在重做堆疊；重做反之；重新命名的紀錄移除。並用 `record` 的快照寫回工作區 meta
  - 「保留結果」補做整批搬完後該寫的紀錄：復原寫回 meta 並轉入重做堆疊；重做轉回復原堆疊；重新命名照提示所說不補寫復原紀錄（無法復原），只清空重做堆疊
- 還原時檔案已不在紀錄位置者略過並列出；搬不回去者留在原地，搬移歷程為其寫殘留紀錄（標示被中斷的操作種類），UI 套用其路徑

### 結果套用到哪個專案

- 結果的 `changes`（原位置 → 目前位置）交給這批搬移所屬的專案套用、標記未存檔
- 所屬專案不是目前專案時（例如啟動時還沒開啟任何專案），照一般開啟流程開啟它：目前專案有未存檔的修改先詢問是否儲存，選取消則什麼都不做；`ProjectAccess.open` 開啟後先套用路徑變動，不把剛搬走的檔列成找不到
- 所屬專案當時尚未存檔、目前專案也沒有引用這批檔案時，提示路徑無法更新
- 主視窗記住這批搬移已套用到哪個專案；之後在同一次執行中選「保留結果」時不再套用一次（對調與連鎖套用兩次會換回去）

### 舊版與損毀的進行中紀錄

- 沒有操作種類的舊版進行中紀錄視為重新命名，也沒有 `record`：「還原」不動堆疊、不寫 meta；「保留結果」照重新命名清空重做堆疊
- 沒有記所屬專案的舊版紀錄套用到目前專案
- 無法讀取（含 `record` 損毀）時提示一次並捨棄

## 復原／重做堆疊

### 紀錄檔

- 兩個堆疊都後進先出。每筆紀錄有唯一 `id`（`UndoRecord.id`），檔名為「推入序號_id.json」（序號 8 位數、補零），序號越大越靠近頂端；在兩個堆疊間轉移時 id 不變
- 舊版以時間戳命名、沒有 id 的紀錄（`undo_YYYYMMDD_HHMMSS.json`，重做堆疊為 `redo_` 開頭）照常載入並能執行，排在新紀錄之下，以去掉 `.json` 的檔名當 id
- 新版寫出的紀錄不保證舊版能正確處理（不支援降版）

### 復原與重做

- 新的操作（重新命名、分割、旋轉）放上復原堆疊並清空重做堆疊
- 復原把整批搬移類紀錄（`MOVE_OPERATIONS`）的檔案搬回原位：已不在新位置的檔略過並列出，專案裡的路徑維持原樣，只有實際搬回的對照轉入重做堆疊。重做同理，已不在原位的檔略過

### 分割與旋轉的紀錄

- 分割與旋轉的紀錄也由搬移歷程組裝（`record_split`、`record_rotate`；旋轉直接覆寫檔案前以 `create_backup` 備份），主視窗與對話框不自己組紀錄
- 復原時，分割的分譜與旋轉另存出的檔移到資源回收桶，旋轉覆寫的檔以備份蓋回；之後移除紀錄、不進重做堆疊（無法重做）
- 復原分割同時退回分割前的專案：結果的 `split` 交給 `Project.revert_split`：
  - 移除新分譜的引用
  - 分割時另建的群組移除，之後才放進去的檔移回未分組
  - 接手的既有群組被分割改掉的樂器表與曲名改回；分割沒改的欄位不動，分割後的修改保留
  - 合併譜已不在專案裡就放回原位置：同一個群組、同樣是分譜或總譜，分譜依其餘分譜間的原順序；原群組已刪除就放回未分組；原本在未分組的本來就沒移動
- 復原後標記未存檔、分頁立即重建
- 重新分割時被取代的舊分譜不找回：主視窗列出它們移到資源回收桶時所在的位置（`replaced_files`），提示仍在資源回收桶（[ADR 0001](../adr/0001-workspace-only-for-generated-files.md) 的取代進資源回收桶不變）
- 沒有合併譜與安置資訊的舊版分割紀錄照常載入，復原時刪除新分譜並移除其引用

## 工作區 meta 快照

復原重新命名會把分譜搬回工作區，需要子資料夾的 `meta.json` 辨識來源，所以復原紀錄帶著工作區 meta 的快照（`UndoRecord.workspace_meta`；`MoveHistory` 因此注入 `WorkspaceService`）：

- 拍快照：重新命名在搬移前、殘留紀錄在寫入時，對來源位於工作區的項目記下其子資料夾的 meta（同一資料夾的不同寫法只記一份）；重做前先以子資料夾目前的 meta 更新快照
- 寫回：復原整批搬完、復原回滾、中斷還原、保留結果的復原，子資料夾若已沒有可讀的 meta 就用快照寫回（`WorkspaceService.restore_meta`），都在刪除進行中紀錄之前；寫回失敗只略過，不影響檔案復原
- 舊紀錄沒有此欄照常載入
